# 襄阳120急救站点管理指导系统

原版四页仪表盘，包含现有站点总览、推荐站点、拆站分析和加站评估。`xy_data/dashboard.html` 与9份前端文件中的页面及结果内容保持原项目字节一致，结果版本为2026年11月13日，范围为现有8站、1716个网格、20834次空间内历史需求。

## 本地运行

只需要Python 3，服务端使用标准库，无需安装额外依赖。在仓库目录运行：

```powershell
python -X utf8 xy_dashboard_server.py
```

然后打开 <http://localhost:8088/dashboard.html>。Leaflet、Chart.js及OpenStreetMap底图需要联网。请通过HTTP服务打开页面，以便加载JSON。

## 地名搜索配置

服务器代理`/geocode`请求腾讯地图POI接口。原项目硬编码的密钥已改为环境变量，密钥不进入仓库。在同一终端中设置自己的密钥，再启动服务：

```powershell
$env:TENCENT_MAP_KEY = "自己的腾讯地图WebService密钥"
python -X utf8 xy_dashboard_server.py
```

`.env.example`仅为配置字段说明，Python服务不会自动加载`.env`。未配置密钥时，地名搜索返回503，其余页面和已有结果仍可使用。

## 静态托管

根目录`index.html`跳转到原版仪表盘，可以在GitHub Pages等静态服务中展示页面、地图和已有分析结果。静态托管不运行Python，`/geocode`地名搜索需要单独的同源后端；完整功能请运行上面的Python服务。本仓库未自动开启公开托管。

## 结果口径

预测目标为出车至到达耗时，不包含接警或调度等待。网格覆盖与历史需求覆盖使用不同分母。同格为真实记录中位数的经验估计，非地图API实测。

加站页使用18点跨星期与采集周聚合情景，单站增量已扣除现有覆盖；候选增益不能相加，潜在转移不等于实际派车减负。布局优化仍采用需求Top400与四时段可达并集，未固定现有8站，所选站数不能解释为最少新增站数或全天覆盖承诺。未模拟两辆救护车配置、车辆容量、排班或忙闲。

## 文件范围

本仓库包含原版前端、运行所需汇总JSON和Python服务。患者级原始出车资料、呼救地址、原始路网大文件、模型训练数据、访问密钥与服务器凭据不随网站上传；原始数据另按交接文件传递。
